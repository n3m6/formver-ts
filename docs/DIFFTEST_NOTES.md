# Differential-test notes (milestone 9)

`src/difftest/` runs every certified function of `examples/pass` through **two** implementations of the same source
and compares them: the original exported JS function, imported through the Bun plugin (so its injected guards,
`@pre`/`@post` and internal checks run), and `interp.ts` over `K.erase(term)` — the kernel term the verifier
certified.  Files: `interp.ts` (interpreter), `gen.ts` (seeded inputs, spec evaluator), `driver.ts`
(`difftestFile`, `deepEqual`, diagnostics, the test-only `tamper` hook).

## Interpreting an erased term

`erase` drops `Sort`/`Pi`/`Sigma`/`Farkas` and keeps `Lam`/`Let` binding one variable, so de Bruijn indices survive
and the interpreter never needs a type.  Values: `Int` is a `bigint` (exact past `2^53`, so an overflow is a
mismatch, not a rounding coincidence); `Vec A n` is a JS array; `Sigma` is `{tag:"pair",first,second}`; `Sum` is
`{tag:"inl"|"inr",value}`, right-nested per variant (the last variant has no `inl`); everything else is one shared
`proof` placeholder.  Ops run on those: `add`/`sub`/`neg`/`mulConst`/`divFloor`/`divTrunc` on bigints, `ifLe`
compares its bounds and applies the chosen branch, `len` is the length, `get`/`append`/`slice`/`castVec` are array
operations, `case` dispatches on the injection tag, and `J` returns its base case.  **`fixWf` is real recursion**:
the induction hypothesis is a value that consumes the new state and its two measure proofs and calls `fixWf` again;
further arguments (a recursive function's preconditions, a loop's invariant) apply to the result.

**Proofs are irrelevant and never throw.**  The kernel's per-op `irrelevant` mask is honoured, so a proof argument
is not evaluated at all; where a proof *is* passed (`ifLe`'s branches, `byContra`, `fixWf`) it is the placeholder.
Every operation is total: applying a non-function, projecting a non-pair or doing arithmetic on a placeholder
yields the placeholder.  Only a bounded step budget throws (`InterpBudgetError`), so a non-terminating tampered
term is reported rather than hanging. `interpTerm(term, {globals})` returns `(args) => value`, one argument per
`Lam` (pass `proof` for proof binders); `GlobalTable` resolves `Const` lazily and memoised (a self-referential
`Const` yields the placeholder instead of looping); `projectPath`, `encodeSum`/`decodeSum`, `pair`/`inl`/`inr` and
`showValue` are the projections onto the packed result.

## The generator and the spec evaluator

`gen.ts` has a seeded `mulberry32` PRNG (no packages): integers from `[-1000, 1000]` plus the edge values `0`,
`±1`, `±(2^53-1)`, arrays of length 0..8, and one variant per union with its fields generated by type. A candidate
is accepted only when **every** `@pre` evaluates to `true`, else it is redrawn up to `maxAttempts` (default 100)
per input, after which the input is *given up* and counted — never replaced by one that violates `@pre`.
`generateInputs` reports attempts/rejections/give-ups, and a seed reproduces its inputs.

`evaluateSpec(e, env)` is the single evaluator of the extractor's spec-expression AST against ordinary JS values
(parameters by binder id and name, `result`, `a.length`, `a[i]`, ternaries, `&&`/`||`/`!`, comparisons, arithmetic,
`InRange`, the `Math.*` prelude). It serves `@pre` and `@post` alike — there are no per-example predicates;
anything it cannot read yields `undefined`, which counts as *not holding*.

## The driver

`difftestFile(path, {count = 200, seed, maxAttempts, tamper, only})` verifies the file (cached by content), imports
the module (the plugin injects the runtime checks) and runs `count` inputs per certified function through both
implementations. A failure is a record (`kind`, input, values, both results, `@post` text, message): `mismatch`
(results not deeply equal — a bigint never equals a number), `post` (a `@post` fails on the original's result, or
cannot be evaluated), `call`/`interpret` (one side threw), `no-inputs` (no candidate met `@pre`). Imported callees
are resolved by **elaborating the imported file too**: a cross-file call is an `external` declaration with a type
but no body, so `percent` can only interpret `clamp` once `clamp.ts` has been verified and registered as a
definition.

## How faithfulness is tested

`test/difftest/unfaithful.test.ts` tampers with an elaborated term — it swaps the two branches of `abs`'s single
`ifLe` — and asserts that the differential test reports a mismatch on a real input (`abs(5)` becomes `-5`, the
exact negation), with the untampered file passing as a control.  A third case tampers with the imported `clamp`'s
body and shows `percent` diverging, which also proves the cross-file definitions are interpreted.  The `tamper`
option is **test-only**: the driver, verifier and plugin never pass one, and a tampered term never reaches the
kernel.  The milestone also found and fixed two real bugs: `===`/`!==` conditions were elaborated as a single
`ifLe` (`<=`), which the kernel accepted but which did not compute the source (`binarySearch` returned `mid` when
`a[mid] < target`); and the injected loop decrease monitor kept state per source location across *calls*, so a
second call raised a spurious `measure-decrease`.

## Known limits

- Evidence, not proof: only a mismatch an input exposes is found.  A `<`-for-`<=` slip at a boundary where both
  branches agree (or `-0` vs `0`) is invisible, and 200 inputs prove no equality.
- `@post` is evaluated on the *original's* result; when the injected check is present it fires first, so the
  `post` record matters mostly where checks are stripped.
- Array elements are opaque: the generator uses integers (the only concrete element type the fragment accepts),
  so element-level reasoning is untested, and `a[i]` in a `@pre` fails extraction (only unit-tested).
- The plugin must be preloaded for the injected checks to run, one process shares one imported module instance,
  and the interpreter is untrusted scaffolding: it can be wrong the same way the elaborator is, and it
  deliberately *does* reduce `fixWf` where the kernel has no rule for it.
